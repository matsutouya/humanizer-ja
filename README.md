# Humanizer JP

AIで作った日本語の下書きを、書き手自身の文体に近い自然な日本語へ整えるClaude Code Skillです。

[blader/humanizer](https://github.com/blader/humanizer) にインスパイアされ、日本語特有のAI文章パターンを整理しました。

---

## なぜ作ったか

英語AI文章のAIっぽさは「統計的に選ばれやすい語彙が集中する」ことから目立つ場合があります。

日本語では、それに加えて**3つの構造的な癖**が目立ちやすくなります：

1. **敬語による行為主体の消失**（「させていただきます」連発で誰が何をするのか消える）
2. **主語省略による書き手の消失**（「私」「僕」が出てこず、誰が考えているか分からない）
3. **です・ます均質化**（文末がすべて「です」「ます」で揃う）

英語版humanizerをそのまま日本語に適用しても、これらの構造的な癖には対応しきれません。Humanizer JPは、日本語向けの編集ルールとして40パターンを3階層で整理しています。

---

## 特徴

- **40パターン**を3階層で体系化（構造的・語彙的・書式的）
- **6軸の「書き手らしさ」**で文体を調整
- **2層モデル（Identity層 / Surface層）**でアカウント一貫性とランダム性を両立
- **基調統一ルール**でですます調と常体の混在を防ぐ
- **「、」の打ち方ガイド**で機械的な読点を除去
- **書き手設定（writer-profile.md）**で自分のキャラクターに合わせた文体に変換
- 現代日本語のWeb発信（note・ブログ・SNS）で見られる自然な文体を観察・整理

---

## 2層モデル：アカウント一貫性とランダム性の両立

humanizer-ja を運用するときに最も注意するのが、**「humanizer通したな」とバレる新しいAIテンプレ**を作らないことです。6軸（一人称・接続助詞・弱い主張・呼びかけ・口語強調・曖昧な感情）を**1段落で全部踏むと**、その組み合わせ自体が新しいテンプレ感を生みます。

これを避けるために、文体を**2層**で考えます。

| 層 | 中身 | 性質 |
|---|---|---|
| **Identity層（不変）** | 一人称・絶対使わない語尾・訴求軸・感情の出し方・口調の階級 | アカウントを見分ける指紋。**毎回固定**。 |
| **Surface層（変動）** | どの語尾を引くか・文長・段落構成・読点・体言止めの頻度 | 同じ書き手でも投稿ごとに揺れる部分。**ここにランダム性を入れる**。 |

### pool として引く運用

`writer-profile.md` の「よく使う語尾」を **pool（5〜8個の候補）** として捉え、**1投稿で2〜3個までしか引かない**。pool 全部を毎回踏もうとするとテンプレ感が出ます。

```
語尾pool（例）：〜です／〜ます／〜だと思います／〜気がする／〜なんですよね／〜と見てます／〜はず／体言止め

→ ある投稿では「〜です」と「〜気がする」と体言止めだけ使う
→ 別の投稿では「〜なんですよね」と「〜はず」だけ使う
```

軸2〜軸6も同じです。**全部踏むのではなく、その段落に必要な軸だけ引く**。

詳細は `SKILL.md` の「アカウント一貫性とランダム性の両立（2層モデル）」セクションを参照。

## 使い方

### 基本の使い方

Claude Codeで以下のように呼び出します：

```
/humanizer-ja

[自然な文体に整えたい日本語の下書きを貼り付け]
```

### 書き手設定を使う

`writer-profile.md` テンプレートを自分用にカスタマイズして、文体を寄せることができます。

1. `writer-profile.md` をコピーして、自分のアカウント名で保存
2. テンプレートの9項目を自分の言葉で埋める
3. humanizer-ja を使うときに一緒に渡す

```
/humanizer-ja

writer-profile.md の内容に従って、以下の文章を自然な文体に整えてください：

[書き手設定の内容]

整える文章：
[AI文章]
```

ビジネス系・日常系・カジュアル系など、複数のキャラクターを使い分けたい場合は、それぞれ別の設定ファイルを作成してください。

例：
- `writer-profile-business.md`
- `writer-profile-casual.md`
- `writer-profile-formal.md`

## このSkillの守備範囲

**対象：** AIっぽさが残った日本語の下書きを、文脈に合う自然な文体へ編集すること

**対象外：**
- ハッシュタグの選定
- SNS運用戦略
- 投稿タイミング・頻度
- マーケティング戦略
- 売上アップの提案

このSkillは「AIっぽい日本語の下書きを、書き手自身の文体に近づける」ための編集ツールです。

---

## 検出する40パターン

### 階層1：構造的パターン（10個）— 修正すると文章が大きく改善しやすい

1. 敬語による行為主体の消失（「させていただきます」過多）
2. 主語の完全消失
3. です・ます均質化
4. 「〜と考えられます」「〜とされています」逃げ
5. 「〜という点において」「〜という観点から」
6. 結論が最後に来すぎる構造
7. 接続詞の機械的連打（「また」「さらに」「加えて」）
8. 受動態の連発・主語なし断片
9. 体言止めリストの濫用
10. 外向きに寄りすぎる（書き手の存在が消える）

### 階層2：語彙・表現パターン（17個）

11. AI頻出語彙＋過剰強調語（「非常に」「多岐にわたる」など）
12. 意義の水増し（「歴史的な転換点」など）
13. 曖昧な出典（「専門家によると」など）
14. 表面分析（「〜し、〜ており」）
15. PR的・広告的表現
16. 定型の「課題はあるが」
17. be動詞回避（「〜として機能する」など）
18. 否定→肯定の決め台詞
19. 三点セット強制
20. 類義語ローテーション
21. 同語反復を避ける（逆方向の問題）
22. 「まさに〜に他なりません」
23. 過剰な曖昧化
24. 「させていただきます」語尾の連鎖
25. 結論を急ぎすぎる
26. 見せかけの網羅性
27. 機械的な評価語語尾

### 階層3：書式・リズムパターン（13個）

28. 短文連打（ブツ切れリズム）
29. 演出読点
30. 読点の乱打
31. 太字の乱用
32. 太字小見出し＋同内容リスト
33. 絵文字デコレーション
34. チャットボット残滓＋べた褒めトーン
35. 前置き宣言
36. 一定間隔改行
37. 結語の汎用化
38. 弱い主張の語尾を使わない
39. SNSの決め台詞依存
40. 「！」の連打

詳細とBefore/After例は `SKILL.md` を参照してください。

## Before / After 例

### Before（典型的な日本語AI文章）

> 素晴らしいご質問ですね。本日は生成AIの活用についてご説明させていただきます。
>
> 生成AIは、現代のビジネスにおける変革の象徴として、その重要性がますます高まっています。メール作成や議事録の要約など非常に多岐にわたる分野において幅広く活用され、作業時間の短縮にも貢献すると考えられます。
>
> 課題もありますが、今後の展開が注目されます。本記事がご参考になれば幸いです。

### After（Humanizer JPで変換）

> 生成AI、半年くらい業務で触ってみての話です。
>
> 一番効いたのはメールと議事録の要約。メールは15分かけてた返信が3分で終わるし、議事録は会議直後に下書きが出てる。地味だけど積み重なるとけっこう違う。専門領域の要約はちょっと微妙でした。前提を知らないと抜けに気づけないので。
>
> 結局、丸投げじゃなくて叩き台を作らせるくらいがいい。今のところはこの距離感で落ち着いてます。

## 文体分析の観察対象

このSkillは、現代日本語のWeb発信（note・ブログ・SNS）で広く使われている自然な文体パターンを観察して作られています。

特に以下のような特徴を抽出しました：

- 接続助詞ネットワーク（「〜なんですが」「〜なんですよね」「〜ので」）
- 弱い主張の語尾（「〜と思います」「〜気がします」）
- 読者への呼びかけ（「〜じゃないですか」）
- 口語強調（「結構」「かなり」「めちゃくちゃ」）
- 話し言葉と書き言葉の自然な混合

これらは特定の書き手の文体ではなく、**現代日本語のWeb発信で読まれているコンテンツに広く見られるパターン**です。
