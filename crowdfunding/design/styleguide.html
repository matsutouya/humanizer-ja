01 — Principles

3つの原則

クラウドファンディングの UI は、突き詰めると「信用できるか」「いくら集まっているか」「いま支援すべきか」の3つにしか答えていない。以下の判断はすべてそこから導かれる。

原則1 — 金額が主役

ページ内で最も強い視覚的重みは、常に金額。見出しでもロゴでもない。金額には必ず tabular-nums を当てて桁を揃える。桁が揃っていない金額の一覧は、それだけで素人臭くなる。

原則2 — アクセントは1色、使い道は2つだけ

アクセントを使ってよいのは支援 CTA と 進捗バー のみ。見出しにも、アイコンにも、区切り線にも使わない。使った瞬間に、ページ内で最も重要なボタンが埋もれる。ステータス色（成功・警告・危険）はアクセントとは別の役割で、状態を伝えるためだけに使う。

原則3 — 空白は削らない

情報量が多いサービスほど、詰めると安っぽくなる。削るべきは要素の数であって、余白ではない。

02 — Color

カラー

プリミティブ（原色）を実装から直接参照しない。必ずセマンティックトークン経由で書く。これを破ると、後からダークモードを足せなくなる。

Neutral — わずかに寒色へ振ったグレー

純粋なグレーは「何も考えていない」色に見える。青緑側にわずかに寄せることで、アクセントの赤と補色の関係になり、白基調が締まる。

Accent — コーラルレッド

なぜ 600 なのか。 明るいコーラル（#ff5a4d 等）は白背景で 3.1:1 しかなく、文字色として使えない。 600 まで深めると 4.59:1 になり、塗りボタンの白文字・白背景上のリンク文字の両方で AA を満たす。 1色で全用途をまかなえるのは、システムとして大きな利点。

03 — Typography

タイポグラフィ

Web フォントを読み込まない。これは妥協ではなく設計判断。日本語 Web フォントは軽量でも数百KB〜数MBあり、LCP が壊滅する。SNS 流入が主で、モバイル回線での初回表示速度がそのまま支援率に効くため、美しさより速度を取る。

06 — Badges / Alerts

バッジ・アラート

ステータス色は状態を伝えるためだけに使う。装飾に使うと「意味のある色」であることが伝わらなくなる。また、色だけで情報を伝えない。「残りわずか」は色と文言の両方で示す。

10 — Forms

フォーム

入力文字サイズは 16px 未満にしない（iOS で自動ズームが発生し、支援フローが破綻する）。ラベルは <label for> で必ず紐づけ、プレースホルダをラベル代わりにしない。

FIELD — STATESdefault / focus / error / disabled
リターンのお届け先として使用します
郵便番号はハイフンなしの7桁で入力してください
プロジェクトページに公開されます
リターンの選択によって決まります
エラー文言は「何が起きたか」＋「どう直すか」。 「入力エラー」では直せない。「郵便番号はハイフンなしの7桁で入力してください」と書く。 日本語フォーム（氏名・住所・電話番号）のパターンはデジタル庁デザインシステムを規範として踏襲する （docs/14-design-system-stack.md §4.1）。ここで独自性を出す意味はなく、 間違えると支援が完了しない。

13 — Motion

モーション

トークン時間用途
instant100ms色の変化・ホバー
fast150msボタンの押下
base200ms影・変形・展開
slow300msモーダル・ボトムシート
deliberate500ms進捗バーの伸長

--ease-standard: cubic-bezier(.2,0,0,1) を既定にする。

動かすもの: ホバーの影、進捗バー、モーダル、トースト、スケルトン、達成の瞬間。
動かさないもの: それ以外。とくにスクロール連動アニメーションは入れない。支援の邪魔になるうえ、モバイルで重い。

prefers-reduced-motion: reduce で全アニメーションを 0.01ms に落とす。この仕様書自身も対応済み。

14 — Accessibility

アクセシビリティ（WCAG 2.2 AA）

リリース前に全項目を確認する。日本語 UI 固有の論点は、デジタル庁デザインシステムを規範として参照する。

  • 本文・補助テキストがすべて 4.5:1 以上（§02 の実測値で担保済み）
  • 大きい文字（18px 700 以上、または 24px 以上）は 3:1 以上
  • すべてのインタラクティブ要素に focus-visible のリング（2px / offset 2px）
  • タブ順序が視覚順序と一致している
  • 進捗バーに role="progressbar" と aria 属性。aria-valuenow は 100 で頭打ち
  • 画像に適切な alt。装飾画像は alt=""
  • 色だけで情報を伝えていない（「残りわずか」は色＋文言）
  • フォームのラベルが <label for> で紐づいている
  • エラーが aria-describedby で入力欄に紐づいている
  • タップターゲットが 44×44px 以上
  • prefers-reduced-motion に対応している
  • ページに lang="ja"
  • 見出しレベルが飛んでいない（h1 → h3 にしない）
  • モーダルでフォーカストラップ、Esc で閉じる
  • 支援完了などの動的更新を aria-live で通知
  • 入力文字サイズが 16px 以上（iOS の自動ズーム防止）
