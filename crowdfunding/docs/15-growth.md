# 15. 立ち上げとグロース戦略

「どうやって盛り上げるか」。プロダクトより難しく、失敗の9割はここで決まる。

---

## 0. 先に、残酷な事実を3つ

### 事実1 — 支援者の大半は、プラットフォームから来ない

クラウドファンディングの支援は、**その出品者が自分で連れてきた人**が中心。
「サイトを見に来た知らない人が支援してくれる」のは、案件が育ってからの話。

つまり**立ち上げ期のプラットフォームの仕事は集客ではない。**
出品者が自分の知り合いを動員するのを、どれだけ助けられるか。ここに尽きる。

### 事実2 — 「誰でも出品できるサイト」は、誰も来ないサイト

両面市場のコールドスタート問題。
支援者は「面白い案件がないと来ない」、出品者は「支援者がいないと出さない」。
両方を同時に集めようとすると、**両方とも集まらない。**

解は1つしかない。**片側を自分で埋める。**

### 事実3 — 序盤で失速した案件は、ほぼ確実に失敗する

公開直後に伸びない案件は、途中から巻き返すことがほとんどない。
「支援が集まっている案件にさらに支援が集まる」からで、
逆に **0% のまま数日置かれた案件は、それだけで死ぬ。**

だから戦術の重心は、**公開してからではなく、公開する前**に置く。

---

## 1. コールドスタートの解き方 — 「プラットフォーム」を名乗らない

### 最初は「場」ではなく「1つの案件」

```
✕  クラファンサイトをオープンしました！出品者募集中です！
     → 案件ゼロ。誰も来ない。来ても何もない

○  自分たちのアルバムを作るために、自分たちでサイトを作りました
     → 案件が1つある。物語がある。人が来る理由がある
```

**第1号案件を、サイトそのものの宣伝材料にする。**
「バンドが自分でクラファンサイトを作って、そこで自分の作品の資金を集めている」
という構図自体がニュースになる。これは大手プラットフォームには絶対に作れない物語。

### シーンを1つ選んで、そこを完全に取る

「誰でも出品できる」は最終形であって、初期の姿ではない。

```
初期      : 自分たちの音楽シーン（ジャンル / 地域 / ライブハウス圏）に限定
      ↓
成立5件   : 同じシーンの周辺（同じ箱に出るバンド、対バン相手、レーベル仲間）
      ↓
成立20件  : 音楽全般（クラシック、DTM、アイドル、吹奏楽…）
      ↓
その先    : 他カテゴリを開放
```

**「音楽のクラファンならここ」と言われる状態を先に作る。**
CAMPFIRE と正面から総合で戦っても勝てない。勝てるのは狭い領域の深さだけ。

> **シーンの選び方。** 自分たちが**すでに顔が利く**範囲にする。
> 知らないシーンに営業しても相手にされない。半径の狭さは弱点ではなく、初期の唯一の武器。

## 2. 第1号案件（自分たちのアルバム）の設計

**ここが失敗したら、サイトは終わり。** 全リソースを注ぐ。

### 公開前にやること（ここが本体）

| 時期 | やること |
|---|---|
| 3ヶ月前 | 制作過程の発信を開始（スタジオ、曲作り、失敗も込みで） |
| 2ヶ月前 | **事前登録ページを公開**。「公開したら通知する」メールを集める |
| 1ヶ月前 | リターン内容を確定。価格帯を3段階以上 |
| 2週間前 | 個別に連絡する人のリストを作る（後述） |
| 1週間前 | 「◯月◯日 20時スタート」を全チャネルで告知 |
| 前日 | 事前登録者へリマインド |

**事前登録の数が、そのまま初動になる。** ここを飛ばして公開すると、必ず 0% で数日を過ごす。

### 「個別に連絡する人リスト」を作る

これが最も効く。そして最も面倒なので、みんなやらない。

```
名前 / 連絡手段 / 想定支援額 / 連絡担当 / 連絡済み / 支援済み
──────────────────────────────────────────
家族・親戚          10〜15人
バンドメンバーの知人  各20人
ライブの常連客      30〜50人
学生時代の友人      20〜30人
仕事関係            10〜20人
SNSでよく絡む人      20〜30人
```

**目標: 100人以上。** SNS に投げるだけの「一斉告知」は、個別 DM の1/10も効かない。

- 公開の**前日から当日**に、**1人ずつ**連絡する
- 「支援して」ではなく「明日公開するから見てほしい」
- 断られてもいい。**シェアだけでも十分な貢献**だと伝える

### ローンチ当日の設計

```
20:00  公開
       ↓ 事前登録者へ一斉メール
       ↓ 全メンバーが同時に SNS 投稿
       ↓ 個別連絡リストの上位から順に DM
       ↓
初日で目標の 20〜30% に乗せる
```

**初日にどれだけ乗せられるかが全て。** ここで勢いがつくと、
それを見た人が「もう少しで達成しそう」と思って乗ってくる。

### 期間中の3つの山

支援は平坦には集まらない。**必ず中だるみする。**

```
支援額
  │  ▲                              ▲
  │ ╱ ╲                            ╱│
  │╱   ╲__________________________╱ │
  └─────────────────────────────────┴──
   公開直後      中だるみ期        ラスト48時間
   （最大の山）  （何もしないとゼロ）（2番目の山）
```

| 時期 | 打ち手 |
|---|---|
| 公開直後 | 事前準備の消化。とにかく初速 |
| 中だるみ期 | **活動報告を止めない。** 週2回。制作の進捗、支援者への感謝、リターンの詳細 |
| 折返し | 「達成率◯%」の節目投稿。新しいリターンを追加するのも有効 |
| ラスト1週間 | 「残り◯日」のカウントダウン開始 |
| **ラスト48時間** | **全力。** 全メンバーが再度個別連絡。「終わります」は強い |

**「終わる」は「始まる」より強い動機になる。** 最終日の追い込みは必ず設計する。

## 3. 出品者を10人集めるまで

### 最初の10人は「募集」しない。口説く

フォームを作って待っても誰も来ない。**こちらから声をかける。**

対象の優先順位:

1. **自分たちの対バン相手・レーベル仲間** — 顔が利く。断られても関係が壊れない
2. **ライブハウスの店長・ブッキング担当** — 出演バンドを紹介してもらえる
3. **すでに他社でクラファンをやったことがある人** — 仕組みの説明が要らない
4. **やりたいと言っているがやり方が分からない人** — 最も刺さる

### 「なぜ CAMPFIRE ではなくここで出すのか」に答える

これに答えられないと、誰も来ない。**手数料の安さは弱い理由**（すぐ真似される）。

強い理由になりうるもの:

| 差別化 | 内容 |
|---|---|
| **伴走** | 大手は放置。うちは**ページ作りから一緒にやる**。初期は完全にコンシェルジュでいい |
| **音楽に最適化** | 音源のプレビュー再生、ライブ招待リターンの座席管理、支援者限定の先行試聴 |
| **審査が通っている＝信頼** | 全件審査を「面倒」ではなく「品質保証」として打ち出す |
| **同じシーンの人が見ている** | 音楽ファンが集まる場所。総合サイトより濃い |
| 手数料 | 安い（が、これは最後に添えるだけ） |

> **初期は「手数料を取らない」も選択肢。** 決済手数料の実費だけもらう。
> [13-payment-cost.md](13-payment-cost.md) のとおり、GMV 1,000万円までは手数料収入自体が小さい。
> **その金額を、出品者を増やすことに使ったほうがリターンが大きい。**

### コンシェルジュ運営を恥じない

初期の10件は、以下を全部こちらでやってよい。

- ページの構成を一緒に考える
- 文章を添削する（というか半分書く）
- リターンの価格設計をアドバイスする
- **「個別連絡リスト」を作らせる**（これが最重要。やらない出品者は失敗する）
- ローンチ日を一緒に決めて、当日に伴走する
- 中だるみ期に「活動報告そろそろ出しましょう」と催促する

**スケールしないことを、意図的にやる。**
10件で仕組みが分かってから、それをガイドとテンプレートに落とす。

### 成立率を守る

**失敗案件が並ぶサイトは死ぬ。**

- 初期は「達成できそうにない案件」を通さない。目標金額が身の丈に合っていなければ下げてもらう
- 目標未達が見えている案件には、期間中に運営から介入する
- 初期は **All-in（実行確定型）を推奨**。未達でも受け取れるので「失敗」に見えにくい

**最初の10件の成立率が、その後の全てを決める。**

## 4. プラットフォームとして成立しているかの判定

### 唯一の指標: 支援者が「2件目」を支援するか

```
❌ 全ての支援者が、誘われた1件だけを支援して去る
      → これはプラットフォームではない。ただの決済ページ

✅ 1件目で来た人が、サイト内の他の案件も支援する
      → プラットフォームとして機能し始めている
```

**追うべき指標: 複数プロジェクトを支援した会員の比率。**
これが伸びない限り、案件を増やしても足し算にしかならない。伸び始めると掛け算になる。

### 回遊を作る仕掛け

| 仕掛け | 内容 |
|---|---|
| 支援完了画面 | 「同じカテゴリで、いま応援されているプロジェクト」を3件出す。**ここが最大の導線** |
| 支援完了メール | 同上。数日後にもう一度「あなたが支援した◯◯が達成しました」＋関連案件 |
| 達成通知 | 支援したプロジェクトが達成したときの通知は開封率が高い。そこに次を載せる |
| 締切間近リスト | 「残り3日」の案件を集めたページ。緊急性で回遊を促す |
| 出品者ページ | 同じ出品者の過去案件・次の案件へ |

### 紹介リンクを早く出す

[12-points-gamification.md](12-points-gamification.md) の **Phase 9-a（紹介リンクのみ・ポイントなし）**は、
グロース施策としても最優先。法務論点がなく、実装1日。

> 「あなたのシェアから **127人** が見て、**8人** が支援しました」

**支援者が自分の影響を数字で見られると、拡散が続く。**
ポイントより、この可視化のほうが効く。

## 5. チャネル別の実務

効く順。**上2つで9割**。

### 1位: オフライン（音楽なら圧倒的）

- **ライブ会場**。物販の横に QR コード。MC で30秒話す
- 対バン相手への挨拶回り
- ライブハウスにフライヤー
- **その場でスマホで支援してもらう**（決済が3タップで終わる設計が効いてくる）

**音楽プロジェクトの最大の武器は、すでにファンが物理的に集まる場があること。** これを使わない手はない。

### 2位: 個別連絡（DM・LINE）

前述のリスト。**一斉配信の10倍効く。** 面倒だが、ここを避けたら勝てない。

### 3位: X（旧Twitter）

- 制作過程を継続投稿。**完成品より過程のほうが伸びる**
- 支援してくれた人の投稿を全部引用RT（お礼＋露出）
- 達成率の節目で報告
- **プロジェクトのOGP画像に達成率を焼き込む**（[05-screens.md](05-screens.md)）。シェア時に「もう少しで達成」が見える

### 4位: Instagram / TikTok

- レコーディング風景、曲ができる瞬間、失敗、メンバーの掛け合い
- **音が出せる媒体は音楽と相性が良い**。楽曲の一部を先出しする

### 5位: note・ブログ

- 「なぜこの曲を作るのか」の長文。**支援を迷っている人の背中を押す**
- 「クラファンサイトを自作した話」は開発者界隈にも届く

### やらなくていいもの

| ✕ | 理由 |
|---|---|
| プレスリリース配信（初期） | 費用に対して届かない。実績ができてから |
| 広告出稿（初期） | 案件が1件のうちは回収できない |
| SEO 記事の量産 | 効果が出るまで半年以上。優先度が低い |
| インフルエンサー依頼 | 費用対効果が読めない。**ステマ規制の論点も出る**（[12](12-points-gamification.md) §0.5） |

## 6. 追う指標

**指標を増やしすぎない。** 見るのは5つで足りる。

| 指標 | 意味 | 初期の目標感 |
|---|---|---|
| **成立率** | サイトの信用そのもの | **80% 以上を死守** |
| **複数案件を支援した会員の比率** | プラットフォームとして機能しているか | 10% → 30% |
| 1案件あたりの新規会員数 | 出品者が外から人を連れてきているか | — |
| 公開24時間の達成率 | 事前準備ができているか | **20% 以上** |
| 出品申請数 / 承認数 | 供給側の健全性 | — |

**成立率が最重要。** これが落ちると、出品者も支援者も一気に離れる。
案件数を増やすより、いま走っている案件を成立させるほうが常に優先。

## 7. 12ヶ月の流れ

```
─ 公開前 3ヶ月 ────────────────────────────
  第1号案件（自分たちのアルバム）の準備
  事前登録リストの構築（目標 300件）
  個別連絡リストの作成（目標 100人）
  出品者候補への声かけ（目標 10人と話す）
  サイトは Phase 5 まで完成させる

─ 月1 ─────────────────────────────────────
  第1号案件を公開。ここに全リソース
  他の案件は入れない。1件に集中する

─ 月2〜4 ──────────────────────────────────
  声をかけた出品者から 2〜3件を順に公開
  コンシェルジュで伴走。1件ずつ丁寧に
  成立率 100% を維持する

─ 月5〜8 ──────────────────────────────────
  同じシーンで 5〜10件
  ガイドとテンプレートを整備（伴走を減らす）
  紹介リンク（Phase 9-a）を投入
  「複数案件を支援した会員」が出始めるかを観察

─ 月9〜12 ─────────────────────────────────
  音楽全般へ拡張
  自動化を進める（審査基準の明文化、テンプレ化）
  ここまでの成立率が 80% を超えていれば、次の投資判断ができる
```

## 8. やらないこと

盛り上げようとして、逆に殺すもの。

| ✕ | なぜ | 代わりに |
|---|---|---|
| オープン直後に大々的な広告 | 案件がスカスカの状態を大勢に見せると、二度と来ない | 案件が10件そろってから |
| 「出品者募集中！」を前面に出す | 支援者向けサイトなのか出品者向けなのか分からなくなる | 案件を見せる。出品導線は控えめに |
| 数を増やすために審査を緩める | **失敗案件が1件出ると、成立率とサイトの信用が同時に落ちる** | 数より成立率 |
| 自分たちで支援して数字を作る | 規約でも実装でも禁止している。バレたら終わり | 正直に低い数字を出す |
| 手数料を極端に下げて集客 | すぐ真似される。値下げ競争は体力勝負で負ける | 伴走と専門性で差別化 |
| 全カテゴリを最初から開ける | 何のサイトか伝わらない。審査の負荷も跳ね上がる | 音楽に絞る |
| 支援を煽る演出（残り◯秒！等） | 信用を失う。[07-design.md](07-design.md) の丸め規則にも反する | 事実を正確に見せる |

## 9. 一番大事なこと

**サイトの出来より、第1号案件の中身のほうが大事。**

どれだけ decent なプラットフォームを作っても、載っている企画が退屈なら誰も支援しない。
逆に、企画が魅力的なら、多少不格好なサイトでも支援は集まる。

だから [08-roadmap.md](08-roadmap.md) にもこう書いてある:

> | ずっと | 自分たちの曲プロジェクトの中身（文章・画像・リターン設計） |
> | **サイトより中身が大事。** 第1号が魅力的でないと誰も来ない |

**実装で詰まっている間も、第1号案件の準備は止めないこと。**
事前登録リストと個別連絡リストは、コードを1行も書かずに今日から作れる。
そして、それが成否を最も左右する。
