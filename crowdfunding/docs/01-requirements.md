# 01. 要件定義

## 1. 登場人物（ロール）

| ロール | 説明 | 権限 |
|---|---|---|
| ゲスト | 未ログイン | プロジェクト閲覧・検索のみ |
| 支援者（BACKER） | 会員登録済み | 支援・コメント・支援履歴閲覧 |
| 出品者（CREATOR） | 出品申請が承認されたユーザー | 上記＋プロジェクト作成・編集・活動報告・支援者一覧閲覧 |
| 運営（ADMIN） | 自分たち | 全権限＋プロジェクト審査・強制停止・返金・手数料設定 |

ロールは `User.role` の単一値ではなく、**BACKER は全員デフォルト、CREATOR は昇格、ADMIN はフラグ**として持つ。
つまり `User.role: BACKER | CREATOR | ADMIN` の enum 1本で足りる（CREATOR は BACKER の権限を包含する）。

## 2. コア機能（MVP に必須）

### 2.1 アカウント

- [ ] メールアドレスでの登録・ログイン（マジックリンク方式。パスワード管理を持たないのが一番安全で楽）
- [ ] Google ログイン（任意。あると登録率が上がる）
- [ ] プロフィール編集（表示名・ハンドル・アイコン・自己紹介・SNSリンク）
- [ ] 退会（論理削除。支援履歴は会計上残す必要があるので物理削除しない）

### 2.2 プロジェクト出品（出品者）

- [ ] 出品者申請 → 運営承認で CREATOR に昇格
- [ ] プロジェクト下書き作成
  - タイトル、キャッチコピー、カバー画像、カテゴリ
  - 本文（Markdown またはリッチテキスト）
  - 目標金額、募集期間（開始日・終了日）
  - 資金調達方式（All-in / All-or-Nothing）
- [ ] リターン（コース）設定：金額・タイトル・説明・お届け予定月・数量上限・配送要否
- [ ] 画像アップロード（カバー1枚＋本文中の複数枚）
- [ ] プレビュー
- [ ] 審査申請 → 運営承認 → 公開
- [ ] 公開後の編集（本文・画像は可 / 目標金額・終了日・既存リターン金額は不可）
- [ ] 活動報告の投稿（支援者限定公開の切替あり）

### 2.3 支援（支援者）

- [ ] プロジェクト一覧（新着・人気・締切間近・カテゴリ別）
- [ ] キーワード検索
- [ ] プロジェクト詳細（進捗バー・達成率・支援者数・残り日数・リターン一覧）
- [ ] リターンを選んで支援（Stripe Checkout へ）
- [ ] 上乗せ支援（リターン金額＋任意の追加額）
- [ ] 配送先住所の入力（配送要のリターンの場合）
- [ ] 応援コメント（匿名支援オプションあり）
- [ ] 支援履歴ページ
- [ ] 支援のキャンセル（募集期間中かつ All-or-Nothing のみ）

### 2.4 決済・入金

- [ ] Stripe Connect（Express）で出品者の入金先口座を登録
- [ ] All-in: 支援時に即決済、出品者へ destination charge で自動振り分け
- [ ] All-or-Nothing: カード保存 → 締切時に達成なら一括決済 / 未達なら何もしない
- [ ] 決済失敗時のリトライ・メール通知
- [ ] 返金（運営操作）
- [ ] プラットフォーム手数料の自動徴収

### 2.5 運営管理

- [ ] プロジェクト審査キュー（承認・差戻し・却下＋理由コメント）
- [ ] 出品者申請の審査
- [ ] 全プロジェクト・全支援の一覧と検索
- [ ] 強制非公開・返金操作
- [ ] 通報の受付と対応

### 2.6 通知（メール）

- [ ] 会員登録・ログインリンク
- [ ] 支援完了（支援者へ／出品者へ）
- [ ] プロジェクト審査結果
- [ ] 目標達成通知
- [ ] 募集終了通知（成立／不成立）
- [ ] 決済失敗の督促
- [ ] 活動報告の公開通知（支援者へ）

## 3. スコープ外（今回は作らない）

意識的に切る。ここを削らないと永遠に終わらない。

| 機能 | 理由 | 将来 |
|---|---|---|
| 月額サブスク型支援（ファンクラブ） | 決済モデルが全く別物 | v2 |
| 銀行振込・コンビニ払い | 消込処理が重い。カードのみで開始 | v2 |
| 多通貨・海外向け | 為替と税務が跳ね上がる | やらない |
| スマホアプリ | Web レスポンシブで十分 | やらない |
| DM・チャット | 荒れる。通報対応コストが読めない | やらない |
| SNS フィード・フォロー機能 | クラファンの本質ではない | v2 |
| 動画アップロード | ストレージ費用と変換処理。YouTube 埋め込みで代替 | 埋め込みで対応 |
| レコメンドエンジン | 案件数が少ないうちは無意味 | v3 |
| 独自ポイント・ウォレット | **資金決済法の前払式支払手段に該当しうる。絶対にやらない** | やらない |

## 4. 主要ユーザーストーリー

### US-1: 出品者としてプロジェクトを立ち上げる
> 出品者として、曲を作るための資金を集めたいので、目標金額とリターンを設定したプロジェクトページを作って公開したい。

受入条件:
- 下書き保存ができ、途中離脱しても内容が消えない
- リターンは最低1つ必要、最大20個まで
- 審査申請すると編集がロックされ、運営に通知が飛ぶ
- 承認されると指定した開始日に自動公開される

### US-2: 支援者としてプロジェクトを支援する
> 支援者として、応援したいプロジェクトのリターンを選んでカードで支援したい。

受入条件:
- 未ログインで支援ボタンを押したらログインに誘導し、ログイン後に元のリターン選択状態に戻る
- 数量上限に達したリターンは選択できない（残り0と表示）
- 決済完了後、支援完了ページと確認メールが届く
- 進捗バーと支援者数が即座に更新される

### US-3: 出品者として集まった資金を受け取る
> 出品者として、募集終了後に集まった資金を自分の銀行口座で受け取りたい。

受入条件:
- Stripe Connect のオンボーディングが未完了なら公開できない
- 手数料を引いた金額が入金予定額として表示される
- 入金スケジュールが確認できる

### US-4: 運営として不適切なプロジェクトを止める
> 運営として、規約違反のプロジェクトを公開前に止めたい。

受入条件:
- 審査待ちが一覧で見える
- 差戻しに理由コメントを付けられ、出品者にメールが飛ぶ
- 公開後でも強制非公開＋全額返金ができる

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| 想定同時アクセス | 初期は同時100人程度。Vercel + Postgres で十分 |
| ページ表示速度 | プロジェクト詳細 LCP 2.5秒以内。カバー画像は next/image で最適化 |
| モバイル対応 | 必須。支援の7割はスマホと想定。モバイルファーストで作る |
| SEO | プロジェクト詳細は SSR / ISR。OGP 画像を動的生成（進捗率入り） |
| 可用性 | 99% 程度でよい。決済中の障害だけは Webhook 冪等性で守る |
| セキュリティ | 後述 |
| データ保持 | 支援・決済記録は最低7年保持（帳簿保存の観点） |

### セキュリティ要件（優先度高）

- [ ] 認可はサーバー側で必ず再チェック（UI で隠すだけにしない）
- [ ] 金額はクライアントから受け取らない。**リターン ID からサーバー側で金額を引く**
- [ ] Stripe Webhook の署名検証を必ず行う
- [ ] Webhook の冪等性（`stripe_event_id` を unique 制約で弾く）
- [ ] 在庫（リターン数量上限）はトランザクション内でチェックし、超過を防ぐ
- [ ] 画像アップロードは MIME・拡張子・サイズを検証
- [ ] 本文の Markdown はサニタイズしてから描画（XSS）
- [ ] 配送先住所は個人情報。出品者にのみ・成立後にのみ開示
- [ ] レート制限（ログイン試行・支援作成）

## 6. 用語定義

| 用語 | 英語 | 説明 |
|---|---|---|
| プロジェクト | Project | 資金を集める企画そのもの |
| リターン | Reward | 支援の見返り。金額別のコース |
| 支援 | Pledge | 支援者がリターンを選んで申し込む行為・レコード |
| 支援者 | Backer | 支援した人 |
| 達成率 | Progress | 集まった金額 ÷ 目標金額 |
| 成立 | Success | All-or-Nothing で目標達成、または All-in で募集終了 |
| 不成立 | Failure | All-or-Nothing で目標未達のまま締切 |
| 活動報告 | Update | 出品者が投稿する進捗報告 |
