# 10. 法務・規約まわりの確認リスト

> ⚠️ **これは法的助言ではない。** 実際に公開する前に、必ず弁護士・税理士に確認すること。
> ここに書いてあるのは「何を調べるべきか」のリストであって、「これで大丈夫」という保証ではない。
> 特に決済とお金の預かりが絡むので、素人判断で走らせるとサービス停止や個人責任になりうる。

---

## 1. 事業形態の確認（最優先）

### 購入型に限定する

| 型 | 内容 | 必要な資格 |
|---|---|---|
| **購入型** | 支援に対してモノ・サービスを返す | **原則なし**（通信販売として整理） |
| 寄付型 | 見返りなし | 税務が複雑（贈与税・寄付金控除） |
| 融資型 | お金を貸して利息を得る | 貸金業登録・第二種金融商品取引業 |
| 株式投資型 | 未公開株を取得 | 第一種少額電子募集取扱業 |

**購入型のみを扱う。** 規約にも「本サービスは購入型クラウドファンディングであり、投資・融資・寄付ではない」と明記し、投資性のあるプロジェクトを禁止事項に入れる。

### 資金の流れ

Stripe Connect の destination charge を使えば、支援金は支援者から出品者へ直接流れ、プラットフォームは手数料を受け取る形になる。
**自社口座で一旦全額を預かって後から送金する設計にはしない。** 資金移動業・収納代行の論点が出るため。

- [ ] Stripe Connect の destination charge を使う設計になっているか確認
- [ ] 独自ポイント・プリペイド残高を**作らない**（資金決済法の前払式支払手段に該当しうる）
- [ ] 支援金を長期間プラットフォームに滞留させない

## 2. 必要な表示・規約

公開前に**全部**用意する必要がある。

### 2.1 特定商取引法に基づく表記（必須）

購入型クラファンは通信販売に該当する。**プラットフォーム自身**と**各出品者**の両方で必要。

**プラットフォーム側（`/tokushoho`）に書くこと:**
- [ ] 事業者名（個人なら氏名。屋号だけでは不可）
- [ ] 所在地・電話番号（**開示請求があれば遅滞なく開示する**旨の記載で代替可の場合あり／要確認）
- [ ] 運営責任者名
- [ ] 手数料の内容と金額
- [ ] 支払方法・支払時期
- [ ] 役務の提供時期
- [ ] 返品・キャンセルに関する事項

**出品者側:** プロジェクトごとに出品者の特商法情報を表示する仕組みが要る。
→ `CreatorProfile` に `legalName` / 所在地 / 連絡先を持たせ、プロジェクト詳細の下部に表示する。
→ 個人出品者の住所公開はハードルが高い。**多くのプラットフォームは「請求があれば開示」方式を採用している。要確認事項。**

### 2.2 利用規約（`/terms`）

盛り込むべき条項:

- [ ] サービスの性質（購入型であること・プラットフォームは取引の当事者ではないこと）
- [ ] プラットフォームの責任範囲（**リターン不履行の責任は出品者にあること**）
- [ ] 手数料（率・徴収タイミング・返金時の扱い）
- [ ] 資金調達方式の説明（All-in / All-or-Nothing の違いと決済タイミング）
- [ ] 支援のキャンセル可否
- [ ] 返金ポリシー（どういう場合に返金するか・しないか）
- [ ] 禁止事項（下記）
- [ ] プロジェクトの審査・非公開化の権限
- [ ] 知的財産権（投稿されたコンテンツの取扱い）
- [ ] 免責・損害賠償の上限
- [ ] 準拠法・管轄裁判所
- [ ] 規約変更の手続き

**最も重要な論点: リターンが履行されなかったときの責任。**
プラットフォームは仲介者だと規約に書いても、支援者からは運営に苦情が来る。
運用ルール（催告 → 出品者への是正要求 → 出品停止）と、それを規約に落とし込む作業が必要。
また、消費者契約法により**一方的にすべての責任を免除する条項は無効**になりうる。ここは必ず専門家に見てもらう。

### 2.3 プライバシーポリシー（`/privacy`）

- [ ] 取得する個人情報の項目（氏名・メール・配送先住所・電話番号）
- [ ] 利用目的
- [ ] **第三者提供**（配送先住所を出品者に渡すこと）→ 支援時に明示的に同意を取る
- [ ] 委託先（Stripe・Resend・Vercel・Neon・Cloudflare）
- [ ] Cookie / アクセス解析
- [ ] 開示・訂正・削除の請求方法
- [ ] 問い合わせ窓口

**配送先住所を出品者に渡す点は必ず明記し、支援フローでも同意を取る。**

### 2.4 プロジェクトガイドライン（`/guidelines`）

禁止するプロジェクトの類型。審査基準としても使う。

- [ ] 投資・融資・配当を約束するもの
- [ ] 換金性の高いもの（金券・仮想通貨・ポイント）
- [ ] 医薬品・医療機器（薬機法）
- [ ] 効能を謳う健康食品・化粧品（薬機法）
- [ ] 酒類（酒税法・通信販売酒類小売業免許）
- [ ] 食品（食品衛生法・営業許可・アレルギー表示）
- [ ] 中古品の販売（古物営業法）
- [ ] 権利者の許諾がないコンテンツ（**音楽サービスなので特に重要。カバー曲・サンプリング**）
- [ ] 公序良俗違反・アダルト・暴力
- [ ] 反社会的勢力の関与
- [ ] 景品表示法に抵触する誇大表現（「必ず」「絶対」「業界No.1」）

### 2.5 その他

- [ ] 資金決済法に基づく表示（該当する場合）
- [ ] 古物営業法（中古品リターンを許可する場合）
- [ ] 景品表示法（プラットフォームの広告表現）

## 3. 音楽プロジェクト特有の注意（自分たちの案件）

自分たちの曲を出すなら、これは他人事ではない。

- [ ] **カバー曲・サンプリングの権利処理**。リターンで音源を配布するなら原盤権と著作権の両方が要る
- [ ] JASRAC / NexTone への申請が必要か（配信・複製）
- [ ] 共同制作者との権利配分を文書化（バンドメンバー・エンジニア・アートワーク）
- [ ] リターンに CD を含むなら、製造原価・在庫・配送コストを織り込んだ金額設定になっているか
- [ ] ライブ招待をリターンにする場合、中止時の扱いを事前に決めておく
- [ ] **お届け予定を保守的に設定する。** 遅延はクラファンで最も多いトラブル

## 3.5. 応援ポイント・拡散キャンペーン

詳細な設計は [12-points-gamification.md](12-points-gamification.md)。ここでは法務チェック項目だけ挙げる。

### 資金決済法（前払式支払手段）

- [ ] **有償ポイント（お金で買えるポイント）を作らない。** 作った瞬間に前払式支払手段の登録・供託義務の検討が必要になる
- [ ] 無償配布ポイントのみとする
- [ ] ポイント残高を「預り金」的に見せる表現をしない

### 景品表示法（景品規制）

- [ ] **ポイントを何とも交換できないようにする**（表示・称号・ランキングのみ）
      → 「経済上の利益の提供」が存在しなくなり、景品規制の議論が発生しない
- [ ] 支援額への充当・値引きに使えるようにしない（総付景品規制の対象になる）
- [ ] 抽選・交換所を実装する場合は、事前に弁護士確認
      - 支援が参加条件 → 一般懸賞（取引価額の20倍・最高10万円、総額は売上予定総額の2%）
      - 支援不要 → オープン懸賞（金額上限の規制は撤廃済み）
- [ ] ランク特典に金銭的価値のあるものを入れない

### 景品表示法（ステルスマーケティング規制・2023年10月〜）★見落としやすい

**「ポイントを付与してユーザーに投稿してもらう」は対価の提供にあたり、
その投稿が「事業者の表示」と判断されうる。** 責任を負うのは投稿者ではなく**事業者側**。

- [ ] シェア用テンプレート文に `#PR` を最初から入れる
- [ ] シェアボタン付近に「ポイントが付与されること」を明示
- [ ] 規約・キャンペーンページに対価の存在を明記
- [ ] 「広告表示のない投稿はポイント対象外」と規約に定める
- [ ] 出品者が支援者に拡散を依頼する機能にも同じルールを適用
- [ ] **キャンペーン開始前に弁護士のレビューを受ける**

### 特定商取引法（連鎖販売取引）★見落としやすい

紹介報酬を**多段階**にすると、連鎖販売取引（マルチ商法）に該当しうる。
該当すると概要書面・契約書面の交付義務、クーリングオフ、広告規制が発生し、
**個人運営の範囲を完全に超える。**

- [ ] **紹介報酬は1段階のみ。**「紹介した人の紹介」に報酬を出さない
- [ ] 紹介者に金銭・換金可能なものを渡さない
- [ ] 「紹介すると稼げる」という訴求をしない
- [ ] 紹介の条件として支援や登録料の支払いを求めない

### 個人情報保護法

- [ ] 紹介リンクのクリック記録で **生の IP アドレスを保存しない**（ハッシュ + ソルト）
- [ ] 取得する行動履歴の内容と利用目的をプライバシーポリシーに記載
- [ ] Cookie による紹介元の追跡について同意取得の要否を確認

### 規約に必ず書く（ポイント関連）

- [ ] ポイントに換金価値はなく、譲渡・売買できない
- [ ] 何とも交換できない（あるいは交換可能なものを限定列挙）
- [ ] 不正が確認された場合、運営はポイントを取り消せる
- [ ] 制度は運営の裁量で変更・終了できる。**終了時の扱いを明記**
- [ ] 有効期限（最終獲得から2年など）
- [ ] 退会時にポイントは消滅する
- [ ] 広告表示のない投稿はポイント対象外

## 4. 税務

- [ ] **プラットフォーム手数料は自分たちの売上。** 事業所得として申告する
- [ ] 支援金の売上計上タイミング（リターン提供時か、資金受領時か）
- [ ] 消費税の課税事業者判定（売上1,000万円は当面超えないだろうが、いずれ）
- [ ] インボイス制度（適格請求書発行事業者の登録をするか。出品者から求められる可能性）
- [ ] 出品者への支払調書・源泉徴収の要否
- [ ] 帳簿・取引記録の保存（**Pledge / Payout を物理削除しない設計にしてある理由がこれ**）

**開業届と、必要なら青色申告の申請を先に出しておく。**

## 6. Stripe の審査

Stripe は**プラットフォーム型サービスの審査が厳しい**。本番利用申請時に以下を求められることがある。

- [ ] サービスの詳細な説明（ビジネスモデル・お金の流れ）
- [ ] 利用規約・プライバシーポリシーの URL（**公開済みであること**）
- [ ] 特商法表記の URL
- [ ] 出品者の審査プロセスの説明
- [ ] リターン不履行時の対応方針
- [ ] 想定取引額

**規約類が未整備だと審査に落ちる。** [08-roadmap.md](08-roadmap.md) で Phase 3 の時点から準備を始めるように書いてあるのはこのため。
また、クラウドファンディングは「商品提供が将来になる」ため**高リスク業種**として扱われ、入金保留（リザーブ）を設定される場合がある。これも織り込んでおく。

## 8. 「安全側に倒した」初期構成のまとめ

判断に迷ったら、この構成に戻る。**規制の議論そのものが発生しない形**にしてある。

| 項目 | 安全側の選択 | それによって回避できるもの |
|---|---|---|
| 資金調達の型 | 購入型のみ | 金商法・貸金業法 |
| 資金の流れ | Stripe Connect の直接振り分け | 資金移動業・収納代行 |
| 滞留期間 | 募集終了 + 7日で送金（規約に明記） | 資金滞留の論点 |
| ポイントの発行 | 無償のみ | 資金決済法（前払式支払手段） |
| ポイントの使途 | **何とも交換できない** | 景品表示法（景品規制） |
| 紹介報酬 | **1段階のみ・非換金** | 特商法（連鎖販売取引） |
| シェア報酬 | `#PR` 必須・少額 | 景表法（ステマ規制） |
| 抽選・交換所 | **当面つくらない** | 懸賞規制 |
| 出品 | 全件、公開前に運営審査 | 詐欺案件・権利侵害・Stripe 停止 |
| 出品ジャンル | ガイドラインで制限（酒・食品・医薬品・中古品を除外） | 薬機法・食品衛生法・酒税法・古物営業法 |

**機能を足したくなったら、まずこの表のどこに触れるかを確認する。**
触れる場合は、実装前に弁護士に確認する。実装してから聞くと、作り直しになる。
